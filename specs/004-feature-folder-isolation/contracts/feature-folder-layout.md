# Contract: Feature Folder Layout

**Feature**: [spec.md](../spec.md), amended by `specs/011-refactor-vertical-slice` | **Date**: 2026-08-22 (layout amended 2026-09-12)

This is the canonical layout every feature folder MUST follow. It is derived from the zelo constitution and the vertical-slice refactor (spec 011): there is no `core/` wrapper and no hexagonal `ports/` layer.

## Canonical template

```text
internal/features/<feature>/
├── domain/                     # feature-local domain types and rules
├── services/                   # application use cases
├── handlers/                   # HTTP handlers + Deps + RegisterRoutes
├── repositories/               # feature-exclusive persistence (optional)
└── templates/                  # feature-specific Templ views + *_templ.go (optional)
```

## Placement rules

1. **Feature-exclusive code** (used by only this feature) MUST live inside the feature folder (spec 004 FR-002).
2. **Cross-feature code** (used by more than one feature, or by shared middleware) MUST live in `internal/shared/` and MUST NOT be copied into a feature folder (spec 004 FR-003).
3. **No hexagonal layer**: a feature MUST NOT contain a `core/` wrapper or a `ports/` package (spec 011 FR-002). Dependencies are wired concretely in `cmd/web/main.go`; where a unit test needs a seam, use function-typed fields or a narrow interface co-located in the package that consumes it.
4. **No cross-feature imports**: a feature MUST NOT import another feature's `domain`, `services`, `handlers`, `repositories`, or `templates` (spec 004 FR-004), enforced by `scripts/check-feature-boundaries.sh`.
5. **Naming**: `<feature>` is kebab-case and matches the feature name; Go package names match their directory (spec 004 FR-007).
6. **Tests are colocated** with the code they cover (spec 004 FR-008).
7. **Generated files**: `*_templ.go` files are generated by `templ generate` and committed; they are never hand-edited (constitution Principle V).

## Shared modules

```text
internal/shared/
├── config/          # environment configuration
├── model/           # cross-feature data definitions
├── middleware/      # auth guard, CSRF, logging, recover, security headers
├── security/        # password hashing, session manager, CSRF, token primitives
├── store/           # db open/migrate + multi-feature persistence adapters
├── templates/       # shared layout + error components (atoms/molecules/organisms)
├── httpx/           # shared HTTP handler helpers (render, current user/session, CSRF form helper)
└── testutil/        # shared test database helper
```

## Scaffolding new features

Run `scripts/new-feature.sh <feature-name>` to copy the canonical template
(`scripts/_feature-template/`) into `internal/features/<feature-name>/`,
replacing the `{{FEATURE}}` placeholders. After implementing the feature,
wire it in `cmd/web/main.go` and run `scripts/check-feature-boundaries.sh`.

## Boundary checklist (for review)

- [ ] The change touches only one feature folder plus, if needed, `internal/shared/`.
- [ ] No import path crosses from one feature folder into another feature folder.
- [ ] No `core/` or `ports/` directory exists inside the feature folder.
- [ ] Any code used by a second feature has been moved to `internal/shared/` rather than duplicated.
- [ ] New features were created from this template (spec 004 FR-005).
- [ ] Tests moved with their code and `go test ./...` passes.
