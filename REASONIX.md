# REASONIX.md — zelo

Project instructions for LLM agents working in this repository. Read this first;
it is loaded into every session. The full README (architecture, layout) lives in
`README.md`; feature-by-feature design artifacts live in `specs/`.

## What this is

**zelo** — a GOTTH web app: **Go** + **OAuth** + **Tailwind CSS v4** + **HTMX v4** + **Templ**.
It is a condominium client portal (dashboard, service directory, finance,
tickets, roles/invitations, profile, i18n). Module path:
`github.com/leoarkiteto/zelo` (Go 1.27).

## Architecture (read this before touching code)

- **Composition root**: `cmd/web/main.go` — constructs all stores/services,
  builds `handlers.Deps` per feature, calls each feature's `RegisterRoutes(mux, deps)`,
  then wraps the mux in the middleware chain (`Recover → Logging → SecurityHeaders →
  WithLocale → WithUser → CSRF`).
- **Vertical slices**: one folder per feature under `internal/features/<feature>/`
  (see `specs/004-feature-folder-isolation/contracts/feature-folder-layout.md`):
  - `domain/` — feature-local domain types/rules
  - `services/` — use cases (plain structs; no ports/adapters layer)
  - `handlers/` — HTTP handlers + `RegisterRoutes`
  - `repositories/` — feature-exclusive persistence (optional)
  - `templates/` — feature Templ views (optional)
  There is **no `core/` wrapper and no `ports/` package**;
  `scripts/check-feature-boundaries.sh` rejects them.
- **Shared code**: cross-feature code lives in `internal/shared/` (`config`,
  `model`, `middleware`, `security`, `store`, `templates`, `httpx`, `i18n`,
  `testutil`) and is **never copied into a feature folder**.
- **Sessions are Redis-backed** (`store.NewRedisSessionStore`, `REDIS_URL`); the
  PostgreSQL `sessions` table is legacy and unused. CSRF tokens ride in the session.

## Hard rules — violations fail CI (`make check`)

1. **No cross-feature imports.** A feature must not import another feature's
   `internal/features/<other>/` packages; it may import its own sub-packages,
   `internal/shared/`, and `cmd/web`. Enforced by
   `scripts/check-feature-boundaries.sh`, which also rejects any `core/` wrapper
   or `ports/` package inside a feature folder.
2. **Shared Templ atomic layers.** `internal/shared/templates/` is split into
   `atoms/` → `molecules/` → `organisms/`. Atoms must not import molecules or
   organisms; molecules must not import organisms; no shared template package
   may import `internal/features/**`. Enforced by
   `scripts/check-template-atomic-boundaries.sh`.
3. **Never hand-edit `*_templ.go`.** They are generated by `templ generate`
   and committed; always edit the `.templ` source and regenerate.
4. **Tailwind v4.** Edit sources in `assets/css/input.css` (design tokens live
   in its `@theme`), rebuild with `make tailwind`, commit the compiled
   `web/static/css/output.css`. Tailwind v4 auto-detects sources, no config.
5. **Feature wiring.** A new feature is not live until its `RegisterRoutes` is
   called in `cmd/web/main.go` (and the integration harness in
   `tests/integration/integration_test.go` if end-to-end coverage is wanted).
6. **Config via env.** All configuration flows through `internal/shared/config`
   (`DATABASE_URL`, `REDIS_URL`, `SESSION_SECRET`, `PASSWORD_PEPPER`,
   `APP_ENV`, `HTTP_ADDR`, `UPLOAD_DIR`). Copy `.env.example` → `.env`; `.env`
   is gitignored. `make` loads and exports `.env` automatically.

## Test strategy

- **Unit tests are colocated** with the code they cover (e.g.
  `internal/shared/security/password_test.go`, `internal/shared/i18n/...`).
  Run with `go test ./...` — no external services needed.
- **Integration tests** live in `tests/integration/` and spin up the full
  composed router against real PostgreSQL + Redis. They **skip** unless
  `TEST_DATABASE_URL` and `TEST_REDIS_URL` are set; use
  `internal/shared/testutil` helpers (per-test DB names, Redis flushing).
  Run them with docker services up:
  `TEST_DATABASE_URL=... TEST_REDIS_URL=... go test ./tests/...`
- Full-app flows are exercised via `httptest` with a cookie jar + CSRF token
  scraping (`csrfFrom`, `postForm`, `getPage` helpers in
  `tests/integration/integration_test.go`).

## Conventions to keep

- Feature folders are kebab-case; Go package names match their directory.
- Handler packages export `Deps` + `RegisterRoutes`; services take their
  dependencies via plain struct fields — concrete store/security types, or
  function values where a unit test needs a seam — with `Now` injectable for
  time (no constructor ceremony, no ports layer).
- RBAC: roles are `owner` / `tenant` / `syndic` per condominium; tenant
  cannot become syndic; only the syndic grants roles. Access control lives in
  `internal/shared/middleware` + per-feature route guards.
- UI follows `docs/design-system.md` (tokens: `steel`, `chrome`, `ink`,
  `canvas`; components: `.btn*`, `.card`, `.table`, `.badge*`, …). Match the
  reference screenshots in `docs/ui`; no new ad-hoc styling.
- i18n: user-facing strings go through `internal/shared/i18n`; see
  `specs/005-i18n-language-switcher/`.

## Common pitfalls

- Forgetting `templ generate` after editing `.templ` files → CI/compile fails
  on stale `*_templ.go`.
- Adding shared UI to a feature `templates/` instead of `internal/shared/templates/`
  → boundary-check failure or duplication.
- Reintroducing a `core/` wrapper or `ports/` package inside a feature — the
  vertical-slice boundary check fails.
- Writing to the old PostgreSQL `sessions` table — sessions are Redis-only now.
- Running `-seed` against production (`APP_ENV=production`) — it refuses on purpose.
- Editing `web/static/js/htmx.min.js` — HTMX is pinned to v4.0.0, vendored under
  `assets/js` and served from `web/static/js`.
- Installing **AlpineJS** when HTMX or Tailwind CSS can already do the task —
  AlpineJS is the **last resort only**: use it only when neither HTMX nor
  Tailwind CSS can handle the required behavior (same vendoring pattern as HTMX:
  `assets/js` → served from `web/static/js`).
